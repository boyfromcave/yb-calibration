# G7 — supply cap and halts

Code: `src/ybcal/studies/g7_supply_halts.py` (WP-7d). Plan: [PLAN.md §5.7](../PLAN.md), facts §1.5-1,
-2, -6. Tests: `tests/studies/test_g7_supply_halts.py`. Decisions: D-WP7d-3, -4, -5, -6.

Owned parameters: `supplyCapBps`, `globalRatioHaltBps`, `recapRatioBps` (derived = 2 × halt, W16 — the
study tunes the parent and reports the child), `divergenceBps`. All locked.

## Structure

Three families (the G5 `Family` framework) on one table of one-at-a-time sweeps around the current set:
`cap` (supplyCapBps), `halt` (globalRatioHaltBps; owns recapRatioBps) and `divergence` (divergenceBps).
Each goes through `decide_with_materiality` (KEEP unless the primary improves by more than
`materiality`; ties toward current; a current value that violates a constraint is always changed;
nothing feasible → BLOCKED with the current value) and `final_verdict` (synthetic → PROVISIONAL).

## Models

### The crash book (`crash_book`)

Hourly paths: a 365-day prefix from `startHeight` (GARCH(1,1)-t placeholder with the log drift removed,
or a demeaned bootstrap of real returns) followed by the first 60 days of `crash-90-30d` and of
`crash-70-1d` (each rescaled to start at the prefix's last price); `g7_paths(budget)` = `paths // 8`
paths per crash. `simulate_vault_book_hours` runs the WP-4 vault book over them with the policy
personas (`g6.agents_config`): exact MINT-4/5/6 verdicts with `issuedZat` = Σ `GetBlockSubsidy` since
`startHeight` (1.5625 YEC a block at 3,075,000; fact 1.5-2), the W20 soft cap (class A at σ = 1 sits
exactly at `recapRatioBps` and bypasses it), HALT-2 from the book's own totals. One book per
`(supplyCapBps, globalRatioHaltBps)`; `divergenceBps` is held at the registry value inside the book so the
divergence sweep reuses it (HALT-3's effect on refusals is second order; its own metrics below use the
block-mode medians).

### Block-mode medians

`g1_price_windows.realise` / `prices` (shared memo with G1/G2): `calm-90d`, `crash-70-1d`,
`crash-90-30d`, `pump-dump-3x`, `flash-wick-50-1h` through the oracle at the candidate's windows,
`g1.paths_for(budget)` paths.

## Metrics (precise definitions)

| Metric | Definition |
|---|---|
| `liq.demand_total_usd` | per path and day: Σ over ACTIVE vaults whose claim path has opened and that fall under `claimThresholdBps` at the **true** price that day (first such day only) of their collateral value; per path the maximum over the crash window; p95 over paths; the worse of the two crashes. The volume claimants would have to sell for the system to stay whole — independent of whether a claim pays (WP-4 finding 3: it rarely does) |
| `liq.demand_bound_usd` / `liq.demand_exempt_usd` | the same restricted to vaults below / at or above `recapRatioBps` (cap-bound B/C vs cap-exempt class A) |
| `liq.claims_max_day_usd` | the book's actual claimant sales (`metrics.liquidation_volume`), same aggregation |
| `liq.budget_usd` | `max_depth_fraction` × p10 of `env.data["depth"].volume_24h_usd`, else × the $25,000 placeholder |
| `book.global_ratio_true` | median over paths of collateral × true price / supply at the end of the prefix (the mature book's ratio) |
| `cap.closed_days_B/C` | per path, days of the prefix on which the MINT-6 headroom `cap − supply` (cap = `⌊⌊issued·p/COIN⌋/10⁴⌋·capBps/10⁴` at the true price, issued since `startHeight`) is below a typical mint (`√(minMint·maxMint)` = $1,000); median over paths; 0 for a class at or above `recapRatioBps` |
| `cap.days_until_admits_bc` | median first prefix day with headroom ≥ a typical mint (365 = never in the first year) |
| `cap.days_first_admit_empty` | `supply.days_until_cap_admits_const` for a typical mint in an empty system at the reference price |
| `cap.bc_refused_share` | B/C attempts refused with `mint-supply-cap` / B/C attempts in the prefix |
| `halt.p_sys_bad` | P(the true price falls to ≤ 10⁴/halt of its level within `grace` blocks), over daily starts of a 5-year hourly ensemble (`paths // 2` paths): a system sitting at the halt level goes under water before any claim can act (fact 1.5-1) |
| `halt.sys_bad_tolerance` | `max_bad_debt_prob` weighted by each class's share of a mature book's outstanding debt (minter class weight × mid-point term) |
| `halt.recall_alarm` | over crash paths (`crash-70-1d`, `crash-90-30d`) where the true system ratio `R0·true(t)/true(fall)` reaches 150 %: share where HALT-2 (`R0·xMint(t)/true(fall) < halt`) fires no later. `R0` = `book.global_ratio_true`; collateral and supply frozen (HALT-2 itself stops new mints) |
| `halt.false_calm` | share of `calm-90d` paths on which HALT-2 fires after the warm-up for the mature book |
| `div.recall` | crash falls caught: HALT-3 fires between a fall's start and one day after its end, over `crash-70-1d`, `crash-90-30d` and the dump of `pump-dump-3x`, per path |
| `div.precision` | TP / (TP + FP); FP = HALT-3 at any time after the warm-up of `calm-90d`, before the dump of `pump-dump-3x` (incl. the rally) and in `flash-wick-50-1h` (a 1-hour wick the medians should ride out), per path |
| `div.f1` | `2PR/(P + R)` |

## Decision rules

| Param | Rule |
|---|---|
| `supplyCapBps` | the **largest** cap (grid of 250 bps; 0 = no cap is excluded) with `liq.demand_bound_usd` ≤ `liq.budget_usd`. The cap can only bound the classes below `recapRatioBps`; class A's demand is reported against the same budget and raised as a design note when it alone exceeds it (D-WP7d-4) |
| `globalRatioHaltBps` | minimise `halt.false_calm` s.t. `halt.p_sys_bad` ≤ `halt.sys_bad_tolerance`, halt < every `baseRatioBps` (§1.4) and `halt.recall_alarm` ≥ `halt_recall_floor`. `recapRatioBps` = 2 × the result (W16); a move that changes which classes bypass HALT-2/MINT-6 at σ = 1 is spelled out in the notes |
| `divergenceBps` | maximise `div.f1` s.t. `div.recall` ≥ `halt_recall_floor` |

## Design notes raised

`design_notes(results, policy)` (also in every G7 `Recommendation.metrics["design_notes"]`):

* **Early supply cap (fact 1.5-2)** — when `cap.closed_days_bc` > `max_class_closed_days`: MINT-6
  measures the cap against the subsidy since `startHeight` (zero at start, 657,000 YEC after a year) and
  counts class-A supply, which bypasses it; class A demand alone fills the cap, so B/C are closed for
  most of the first year at any cap value on the grid. The fix is rule-level (an earlier `issuedZat`
  origin, or a cap sum excluding cap-exempt supply), left to the owner.
* **Cap-exempt liquidation** — when class A's worst-day liquidation demand alone exceeds the depth
  budget: `supplyCapBps` cannot bound it.

## Assumptions

* Liquidation demand counts a vault once, on its first under-threshold day after its claim path opens
  (no liquidation before `claimHeight`, fact 1.5-1); the true price stands in for pClaim.
* The p10 daily volume is a $25,000 placeholder until a depth file is loaded (`ybcal data import
  --kind depth`); the cap decision scales with it one for one.
* The HALT-2 risk horizon is `grace` (the shortest time before a claim can rescue a vault past its term);
  the tolerance is the outstanding-debt-weighted class tolerance (D-WP7d-3).
* The cap headroom uses the true price for pMint.

## How real data changes the answer

* Real hourly prices (`env.data["price"]`): the prefix, the drawdown ensemble behind `halt.p_sys_bad` and
  the scenario bases bootstrap real returns — `globalRatioHaltBps` is the most data-sensitive value
  (fat tails push it up), and HALT-3's calm false positives scale with real volatility.
* A depth file sets the liquidation budget; with it, the cap decision becomes `real-data` (together with
  real prices).
* The early-cap design note does not depend on data: it follows from the rule (`issuedZat` since start)
  and the adoption case.

## Real data, 2026-10 (D-RD-ORA-3, -6, -7)

**HALT-3 on the real history.** With a real hourly price each candidate carries `div.replay_*`
(per era) from `studies/oracle_replay.py`: HALT-3 and NO_PRICE hours per year, the share of real
falls caught (≥ 30 % in a day or ≥ 50 % in a week on 6-hour medians; caught = HALT-3 between the
fall's peak and a day after its trough; `fall1d_recall` for the one-day ones alone), *false* HALT-3
hours (outside every ≥ 20 % weekly fall, from a day before its peak to two days after its trough)
and HALT-3 hours in the day after a real one-hour wick > 20 %. The **availability constraint**
(`calm_availability`, D-RD-AUD-6) reads the worst era's false hours when the replay exists
(`div.real_false_h_max`), because the bootstrap `calm-90d` resamples the real crash days and so
counted correct halts as false (57 h/yr at 25 % against 2–6 h/yr of real false halts).

**HALT-2 on the real history.** `halt.p_sys_bad_real` is P(price ≤ 1/halt of the start within
`grace`) over the real series' daily starts (no bootstrap). At 250 %: 2.5 % on the spliced hourly
series, 4.3 % on the daily series back to 2019, 6.4 % on the 5-year bootstrap, against a tolerance
of 1.6 %; ~300 % meets it. §1.4 (halt < every base ratio, class C 300 %) and W16 (recap = 2 × halt,
D-R-3) with W20's pinned 500 % soft-cap gate (D-R-11) make the level owner-pinned in effect: the
design note states the exposure.
